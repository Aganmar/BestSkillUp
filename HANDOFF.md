# BestSkillUp — hand-off

WoW: Forever add-on that ranks profession recipes by **expected gold per skill point**, using Auctionator prices. Blacksmithing, Leatherworking, Mining (smelting), Enchanting, Cooking and First Aid. Version 0.13.1, Interface 16001. Licensed GPL v3 (`LICENSE`, shipped in the release zip).

- Source (git repo): `C:\Users\User\BestSkillUp`, pushed to the private GitHub repo https://github.com/Aganmar/BestSkillUp
- Install path (managed by WowUp from the GitHub releases): `C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\BestSkillUp`

## Testing between releases

Changes are committed and pushed as usual, but not released after every change. They are copied straight into the game's AddOns folder instead (what a release zip would contain: the TOC, the files it loads, `Media/BestSkillUp.tga`, `LICENSE`), with `Tools/Deploy.ps1` or the same copy done by hand. The TOC's `## Version` stays at the last release until the next one. A release is made once the changes add up to a sizeable difference; WowUp then installs it over the deployed copy.

## Releasing

Bump `## Version:` in `BestSkillUp.toc`, commit and push, then either push a matching tag (`git tag v0.5.1 && git push origin v0.5.1`) or press **Run workflow** on the Release workflow in the repo's Actions tab (it tags the commit `v<TOC version>`). The `Release` workflow (`.github/workflows/release.yml`) checks a pushed tag matches the TOC version, builds `BestSkillUp-<tag>-forever.zip` (the TOC, the files it loads, `Media/BestSkillUp.tga` and `LICENSE`, under a `BestSkillUp/` folder) plus a `release.json` (flavor `forever`), and publishes the GitHub release that WowUp installs from.

## How it works

```
expected cost per point = (reagent cost − value of what you make) ÷ chance to skill up
chance (Classic rule)   = orange 100%, grey 0%, yellow/green = (grey − skill) ÷ (grey − yellow)
```

- **Prices**: AH prices come only from Auctionator. Sharing prices between characters is left to a separate add-on that writes into Auctionator (BestSkillUp's own sync, `Sync.lua` and `Tools/SyncAuctionator.ps1`, was removed in 0.7.0).
- **Reagent cost** (`ns.UnitCost`, recursive, memoised, depth ≤ 5): cheapest of manual override → vendor → Auctionator AH → crafting/smelting it from its own reagents → Wowhead average price (fallback, toggle `useWH`).
- **Value of what you make** (`ns.ResaleValue`): `none` / `vendor` (vendor sell price) / `ah` (AH price × (1 − AH cut) × sell-through, or vendor if higher). BoP items always use vendor value.
- **Disenchant value** (`ns.DisenchantValue`): expected AH value (after cut and sell-through) of disenchanting an uncommon/rare/epic weapon or armour piece, from `D.disenchant` in `Data.lua` (the Warcraft Wiki's Classic tables by **item level**, with every chance and quantity per row; the top rows also cover item level 66+ since WoW: Forever has no TBC materials). Item level, quality and class come from `GetItemInfo`, requested and refreshed when not cached. Items made by Enchanting are excluded (they can't be disenchanted). `ns.ResaleValue` takes it when it beats vendor/AH and `ns.DisenchantCounts(id)` holds: `ns.UseDisenchant()` (`DB.disenchant`, default: the character has Enchanting) and, for bind-on-pickup items, the character itself has Enchanting. Cross-checked against the Siz Disenchanting add-on's table: identical except epics below item level 40 (wiki: rare row) and green weapons at 51+ (wiki: 22/75/3%). Shown in the crafting window as `Cost Per Point (Disenchant)`.
- **Working Overtime** (`ns.Chance` wraps the formula): per-character rank `CDB.overtime` (0-5, Options stepper or `/bsu overtime`). It takes 4% per rank off the chance of *not* skilling up: chances strictly between 0 and 1 become 1 − (1 − p) × (1 − 0.04 × rank). Measured: Lesser Magic Wand 100→115 at 5/5 took 52 crafts (this reading predicts ~44, +20 points ~41, ×1.2 ~111, no talent ~133); per-point likelihood favours this reading ~11× over ×1.2 and ~2× over +20 points.
- **Arcane Salvager option** (`DB.salvagerBonus`, Options checkbox, account-wide, off by default): `rowValue` values each dust/essence drop as `(1 - c) * avg + c * (max + 1)` with `ns.SALVAGER_CHANCE = 0.30`; shards unchanged. From the recordings: boosted results above the Classic maximum are always exactly max + 1; Green Iron Bracers Soul Dust 23 unboosted (matches Classic 2-5 exactly) vs 24 boosted (+27%, p ~ 0.02); max+1 fits ~300x better than +1, x1.5 and x2 ruled out. Chance measured 34% overall (95% 24-45%), dust 24% (15-36%), essences 67% (44-84%): 30% is the working value until more data. Open: Dream Dust 51-55 boosted had only one 6 in 18.
- **Specializations**: `D.specOf[recipeID] = spell` (Data.lua, from Wowhead's per-recipe `specialization` field) and `D.specNames`. `ns.SpecBlocked(id)` (Core) is true when the plan's specialization isn't known (`IsPlayerSpell`) and a rival is: Armorsmith 9788 vs Weaponsmith 9787; the Weaponsmith masters 17039/17040/17041 are blocked by Armorsmith or another master; Dragonscale 10656 / Elemental 10658 / Tribal 10660 block each other. No specialization yet = nothing blocked. `usable()` drops blocked unlearned recipes; the Recipes tab hides them; tooltips show "Needs ...". Next export: include `specialization` in the JSON and generate this list.
- **Master Chef** (Legacy talent): per-character rank `CDB.chef` (0-5, Options stepper or `/bsu chef`). The tooltip at 0/5 says "Your cooking recipes have a 10% chance to create an extra result"; taken as rank 1 = 10%, so 10% per rank (unverified: check the tooltip once a point is spent). `ns.Made(r)` multiplies the average made by `1 + 0.10 × rank` for recipes flagged `r.cook` (set in `ns.AddProfessionData` for skill line 185), which raises the resale value and lowers the per-unit cost of cooked reagents. Doesn't change skill-up chances.
- **Disenchant recording** — dev only, in a separate add-on `Dev/BestSkillUp_Dev/` (folder `AddOns\BestSkillUp_Dev`, `## Dependencies: BestSkillUp`), for measuring the Arcane Salvager, whose bonus isn't published. It's separate because WowUp updating BestSkillUp replaced the local copy and silently removed the recorder (in-file version lost a session of disenchants). Core exposes its namespace as the global `BestSkillUpAPI`; the recorder sets `ns.DevSlash` (Core calls it first from `/bsu`, and lists `salvager` in the help only when it exists) and saves into `BestSkillUpDB.deLog`. Releases never contain it. The Salvager gives the buff **Boosted Disenchanting** (spell 1283701, ~1 h, tooltip: "from time spent near Arcane Salvager. While near Arcane Salvager, chance of bonus disenchanting output is increased"). The first in-game test recorded nothing, so the recorder now has fallbacks at every step: the cast is any `UNIT_SPELLCAST_SENT/START/SUCCEEDED` whose spell is 13262 or named "Disenchant"; the item is the bag item the cast locks, else the bag item clicked while `SpellIsTargeting()` (hooks on `C_Container.UseContainerItem`/`PickupContainerItem`), else the bag item named as the SENT target; the item is also found afterwards as the armour or weapon there is less of than when the cast started (item counts, so bag re-sorting and duplicates don't matter; looked for every 0.5 s for up to 10 s because the item can leave the bags only when the loot window closes). Every way of finding the item only accepts uncommon-epic armour or weapons (a locked Runecloth stack was once taken for the item); the loot comes from `LOOT_READY`/`LOOT_OPENED`, else `CHAT_MSG_LOOT` lines within 5 s of SUCCEEDED (committed after 4 s). A cast with no loot caught prints a warning; `/bsu salvager debug` prints each step. Records store `via` ("loot"/"chat"). The drops are stored in `DB.deLog` (max 3000) with item level, quality, class, Enchanting skill, buff names and spell IDs (`auras`, `auraIDs`) and `boost` (had Boosted Disenchanting). Older records without `boost` are classified by buff name; the old manual switch (`sal`, `DB.salvager`) is ignored and cleared. `/bsu salvager` compares the records with `D.disenchant`, boosted vs not: materials and value against expected, materials per disenchant, how often more than one of the row's materials dropped ("2+ kinds"), a quantity above the row maximum ("over max"), and a material from the next bracket. `/bsu salvager clear` empties the log. Nothing uses the results yet. Open question: whether the bonus needs you near the Salvager or just the buff (disenchant with the buff away from it to tell).
- **Learned thresholds** (`ns.ApplySeen`): each scan records every known recipe's colour at that skill in `DB.seen[spellID][difficulty] = { low, high }` (account-wide). On load and after each scan the recipe's thresholds (`r[5..8]`) are refitted, moving only what the colours seen contradict: the learn level drops to the lowest skill the recipe was seen at, and each colour's start is clamped to after the last skill the previous colour was seen at and no later than the first skill it (or a later colour) was seen at. Everything else keeps Wowhead's value. (Until 2026-11-19 a recipe known early was shifted down whole as a guess; that made Ornate Mithril Helm's grey 256 instead of Wowhead's uncontradicted 260, so it was removed.) Wowhead's values stay in `r.base`; `r.corrected` makes the tooltip say so. Example: Mithril Spurs is trained at 215 in WoW: Forever, Wowhead says 235.
- **Live colour override** (`ns.Chance`): at your current skill, the game's own recipe difficulty wins if it disagrees with the data.
- **Professions**: each `Data_<Profession>.lua` registers itself with `ns.AddProfessionData` (`Data.lua`). The list shows the *active* profession: the one whose window you last opened (`ns.SetActive`), switchable by clicking the list's title or `/bsu prof`. Reagent crafting (`ns.UnitCost`) looks across every profession's recipes; Mining's smelts count as "smelt" (the `reagents.smelt` option, your Mining skill) rather than "craft".
- **Ranking** (`ns.Evaluate(skill, skillLine)`, both default to the active profession): every usable recipe with chance > 0, sorted by cost per point, then chance, then ID. Recipes with an unpriced reagent sort last. Recipes you know always count; the source and "unlearned" filters only apply to recipes you don't know.

## Settings (`BestSkillUpDB`)

`resale` (none/vendor/ah, default vendor), `ahCut` 5, `ahSellThrough` 60, `useWH` true, `reagents` {vendor, ah, craft, smelt}, `includeUnlearned` true, `sources` {trainer, vendor, other on; drop, quest off}, `overrides` [itemID] = copper, `deLog` (recorded disenchants, dev build), `seen` (learned colours), `disenchant` (nil = auto), `point`, `shown`. (`shared`, `partner`, `pushAuctionator` belonged to the price sync removed in 0.7.0 and are cleared on load.)
Per character (`BestSkillUpCharDB`): `profs[skillLine] = { known, scanned, skill, maxSkill }`, `active` (last profession opened), `mining`, `overtime` (Working Overtime rank), `chef` (Master Chef rank). Saved data from 0.5.0 (top-level `known`/`skill`/…) is moved into `profs[164]` on load.

## Data generation

```
python3 Tools/gen_data.py Cooking 185 Tools/data/cooking.json Data_Cooking.lua
python3 Tools/gen_data.py Mining 186 Tools/data/mining.json Data_Mining.lua
python3 Tools/gen_data.py "First Aid" 129 Tools/data/firstaid.json Data_FirstAid.lua
python3 Tools/gen_data.py Leatherworking 165 Tools/data/leatherworking.json Data_Leatherworking.lua
python3 Tools/gen_data.py Enchanting 333 Tools/data/enchanting.json Data_Enchanting.lua
python3 Tools/gen_data.py Blacksmithing 164 <blacksmithing.json> Data_Blacksmithing.lua
```

The inputs are Wowhead (WoW Forever) exports from the profession's skill page (e.g. `https://www.wowhead.com/forever/skill=185/cooking`): `g_listviews.recipes` (colors, reagents, creates, learnedat, source) and `g_items` (jsonequip buyprice/sellprice/avgbuyout), mapped in the browser console into the shape described at the top of `gen_data.py`. The Cooking, Mining, First Aid, Enchanting and Leatherworking exports are kept in `Tools/data/`. **The Blacksmithing export wasn't kept**, so regenerating Blacksmithing needs it scraped again (the optional old-format mining argument is no longer needed) (its data file was converted to the new format by hand, contents unchanged). Notes:
- Thresholds: orange = colors[0], else learnedat; starter recipes (no orange, no trainer, learnedat ≤ 20) are treated as skill 1. Wowhead's `learnedat` is sometimes wrong (e.g. Rough Sharpening Stone).
- Recipes that make an item but have a count of 0 on Wowhead (oils, wands, campfire kits) are treated as making 1.
- Recipes whose grey threshold is 0 (unfinished Wowhead entries such as Cleansing Stew) are left out.
- Wowhead's `buyprice` is a template value, not proof an item is vendor-sold; vendor items come from the `VENDOR_NAMES` list in the script.
- Wowhead rate-limits fast scraping (CloudFront 403) — fetch slowly or in one request per profession.

## Testing / gotchas

- Adding a file to the TOC needs a **full game restart**, not `/reload`.
- `|` in chat text is a WoW escape code — help text uses `/` instead.
- `StaticPopup` data doesn't pass through on Forever; the Shift-click link uses a custom frame.
- EllesmereUI already skins GameTooltip; the add-on uses its own tooltip frames (`BestSkillUpItemTip`, `BestSkillUpCostTip`) and doesn't re-skin them. Other add-ons' tooltip lines (e.g. Auctionator's price) only hook GameTooltip, so the item tooltip adds its own "Auction xN" line from `ns.AHPrice`.
- Logic was tested outside the game with lua5.1 and stubbed WoW APIs; there is no test harness in this folder.

## Open items

1. **Ranking skew (undecided).** With resale on, profitable crafts with a low skill-up chance can outrank reliable ones, because a negative net cost divided by a small chance looks great. Suggested fix: a "profit credit %" setting (count only part of the resale value) plus a "cost per craft" column, so cheap-but-unlikely recipes are visible for what they are.
2. **More professions.** Adding one is: export its Wowhead skill page into `Tools/data/<profession>.json`, run `gen_data.py`, add the file to the TOC (after `Data.lua`, before `Core.lua`), and add any vendor-sold reagents to `VENDOR_NAMES`. Starter recipes often have learn levels from Wowhead that are too high (Cooking's Charred Wolf Meat, First Aid's Linen Bandage, Mining's Smelt Copper); they still show once that profession's window has been opened, because known recipes always count. Mining's list only covers smelting; skill from mining nodes isn't ranked.

## Updating recipe data (any profession)
1. **Wowhead export** (built-in browser on `https://www.wowhead.com/forever/skill=<line>/<name>`): map `g_listviews.recipes.data` + `g_items` into the JSON shape in `Tools/gen_data.py`'s docstring, plus `env` = Wowhead's per-recipe `envChange.status` (new/updated) for reference. Save as `Tools/data/<profession>.json` (kept, so the next export can be compared).
2. **Rebuild and compare**: `python3 Tools/gen_data.py ... /tmp/new.lua` then `python3 Tools/diff_data.py Data_<X>.lua /tmp/new.lua` (added / removed / changed output, amount, colours, source, reagents).
3. **Corrections** (`Tools/data/corrections_<profession>.json`, applied by gen_data on top of the export): colour fixes only where the boundary was observed exactly in game (last skill of one colour and first of the next both in `BestSkillUpDB.seen`), and only when every threshold needed to keep orange <= yellow <= green <= grey is proven that way. Anything contradicted but not pinned goes under `_pending` with its evidence and what's still needed. No guesses.
4. **In-game audit** (dev add-on): open the profession, `/bsu audit`, `/reload`. `BestSkillUpDB.audit[line]` holds every recipe the game lists (learned or not) with output, amounts, reagents, learned colour and source text; chat lists recipes missing from BSU's data and reagent/output differences.
5. Tests + ranking regression, then local deploy; release when asked.

Blacksmithing re-export 2026-11-19: no recipes added or removed and no threshold changes vs 2026-11-15; 7 sources filled in (5 drop, 2 vendor). Colour evidence from 151 recipes: 5 contradict Wowhead, none fully pinned yet (all in `_pending`).
In-game audit 2026-11-19 (skill 251, saved as `Tools/data/audit_blacksmithing.json`): the game lists 506 recipes. All 452 Wowhead recipes are among them with identical reagents and output. The other 54 are Season of Discovery recipe IDs (Obsidian, Icebane, Scarlet Soldier, Razorspike, "Refined"/"Hardened" Arcanite variants, SoD Golden Scale set...), none learned and no source: left out of the data until one is seen learned or sourced. `GetRecipeSourceText` returns nothing on Forever.
